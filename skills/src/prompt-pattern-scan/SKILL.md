# プロンプトパターン解析スキル（系統B）

Claude Code が自動記録するプロンプト履歴を分析し、繰り返し作業パターンを事実ベースで抽出する。
重い履歴読み込み（≈数万トークン）は**サブエージェントに隔離**し、メイン会話のコンテキストを汚さない。

## 構成（単一ロジック源）

- 分析ロジック本体: `~/.claude/prompt-patterns/ANALYSIS_PROMPT.md`（このスキルと launchd 日次バッチが共有）
- 状態ストア: `~/.claude/prompt-patterns/state.json`
- レポート: `~/.claude/prompt-patterns/report-latest.md`

## 手順

### 1. 検出（サブエージェントに委譲）
`general-purpose` サブエージェントを **1体** 起動し、次のプロンプトを渡す:

> `~/.claude/prompt-patterns/ANALYSIS_PROMPT.md` を読み、そこに書かれた手順を上から厳密に実行してください。
> 手順7（state.json 更新）と手順9（report-latest.md 生成）のファイル書き込みは必ず完了させること。
> 戻り値としては、新規候補の一覧（id / 推奨種別 / 直近7日・累計回数 / 作成指示ドラフト）と
> 実行サマリ（解析件数・新規候補件数）だけを簡潔に返してください。履歴の生データは返さないこと。

- サブエージェントが history.jsonl の重い読み込み・クラスタリング・state/report 書き込みまで行う。
- メインはサブエージェントの戻り値（コンパクトな候補一覧）だけを受け取る＝コンテキストを軽く保つ。
- 並列分割（マップリデュース）はしない。現規模では単一サブエージェントで十分（YAGNI）。

### 2. 提示
サブエージェントの戻り値をそのままユーザーに提示する。末尾に必ず次を添える:

> 採用するものがあれば「#N を採用して」、仕組み化しないものは「#N は不要」と指示してください。

### 3. 採用 / 却下（ユーザーが明示指示したときだけ・メインが実行）
**ユーザーが「#N を採用して」と言うまで、スキル/コマンドは絶対に作成しない。**

- 「#N を採用して」: 推奨種別に従い実体を作成する
  - Skill → `~/.claude/skills/<name>/SKILL.md`
  - slash command → `~/.claude/commands/<name>.md`
  - schedule → schedule スキルで登録
  - 作成後、`state.json` の該当パターンを `status: "adopted"`、`linkedSkill`（作成物名）と `decidedAt`（YYYY-MM-DD）を設定して更新。
  - 既存スキルが重複カバーしている候補（notes に記載あり）は、新規作成でなく**既存スキルへの統合 or 振り分けコマンド化**を先に提案する。
- 「#N は不要」: `state.json` の該当パターンを `status: "dismissed"`、`decidedAt` を設定。以後再提案されない。

## 注意
- 生プロンプト本文・具体値（URL・ID・固有名詞・トークン）は state/report に**書かない**（抽象化説明のみ）。
- カウントは LLM クラスタリングに基づく**傾向値**であり、実行ごとに多少揺れる（厳密値ではない）。
