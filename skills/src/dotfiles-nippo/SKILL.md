# 日報生成スキル

Claude Code のセッションログを日報にする。**ツールは事実だけを出し、内省は人間が書く**。
この分担が本スキルの設計の中心で、自動生成された振り返りを読み返しても何も残らないという
上流（nwiizo/nippo, MIT）の観察を採用している。

## 構成（単一ロジック源）

- 事実の集約: `skill-session-digest`（`bin/skill-session-digest` が正本・PATH 上に symlink）
- 出力先: `~/.claude/nippo/YYYY-MM-DD.md`
- 中間ファイル: `~/.claude/nippo/.digest-YYYY-MM-DD.json`（生成後に削除する）

集約は決定的処理なのでスクリプトに閉じ込め、モデルは**要約・言語化だけ**を担当する。
1 日分の生ログは実測 900KB 超あり、そのまま読むとコンテキストに乗らない。

## 手順

### 1. 対象日を決める

引数があればそれ（`YYYY-MM-DD` / `昨日` / `8/20` 等を解釈）、無ければ今日。
ユーザーに聞き返さない。

### 2. digest を作って読む

```bash
mkdir -p ~/.claude/nippo
skill-session-digest <YYYY-MM-DD> > ~/.claude/nippo/.digest-<YYYY-MM-DD>.json
```

特定プロジェクトだけに絞る指示があれば `--project <部分一致>` を付ける。
生成した JSON を `Read` する。**セッションログの JSONL を直接読むことは絶対にしない。**

`stats.prompts_kept` と `stats.tool_calls` が両方 0 なら、その日は記録が無い。
日報を捏造せず「対象日の記録がありません」と伝えて終了する。
`meta.retention_oldest` より前の日付なら、ログが失効している旨も添える。

### 3. 日報を書く

`~/.claude/nippo/<YYYY-MM-DD>.md` に `Write` する。既に同名ファイルがあれば
**上書きせず**、追記か別名かをユーザーに確認する。

構成は以下に固定する。

```markdown
# 日報 YYYY-MM-DD（曜日）

## やったこと
（projects[] ごとに、prompts と tools・git_commands から「何をどこまで進めたか」を
 2〜4 行で。プロジェクト名は cwd の name を使う。ブランチ名があれば添える）

## 判断の記録
| 場面 | 選んだこと | 見送ったこと |
|---|---|---|
（prompts のうち方針転換・選択が現れているものだけ。無ければ表ごと省く）

## 詰まった点
（エラーの再試行、同じファイルへの繰り返し Edit、方針の巻き戻しなど、
 digest から読み取れるものだけ。無ければ「特になし」）

## 統計
- プロンプト: {stats.prompts_kept} 件（ノイズ除去前 {stats.prompts_total} 件）
- ツール実行: {stats.tool_calls} 回（{stats.tools} の上位 3 つ）
- プロジェクト: {stats.projects} / セッション: {stats.sessions}
- 稼働帯: {stats.by_hour} から読み取れる時間帯

## 明日の問い
- 今日いちばん時間を溶かしたのは何で、その原因はどこにあった？
  -
- 明日ひとつだけ変えるなら、何を変える？
  -
```

### 4. 後片付けと提示

`.digest-<日付>.json` を `rm -f` で消し、日報のパスと本文を提示する。

## 厳守事項

- **「明日の問い」に回答を書かない。** 空欄のまま残す。ここを埋めた瞬間にこのスキルの
  価値は消える。同様に「詰まった点」も、digest から観測できない反省を足さない。
- **数値は digest から直接引用し、再計算しない。** 件数を数え直したり推定したりしない。
- **日付は `meta.date` を使う。** 実行日から計算し直さない。
- **digest に無い作業を書かない。** プロジェクト名・ファイル名・コミット内容を推測で
  補完しない。情報が薄い日は薄いまま出す。
- **書籍・記事・URL を紹介しない。** ハルシネーションの温床になる。
- **Python を使わない。** 追加の集計が要るなら `jq` で digest に対して行う。
- **リポジトリ内に日報を書かない。** 出力は `~/.claude/nippo/` 固定。digest には
  private リポジトリ名・ブランチ名・プロンプト本文（顧客名・案件名を含みうる）が
  そのまま入る。実測で 1 日分の 3 割強が社内固有名を含む。dotfiles は public。
- **Bash 出力が途中で切れていたら、その先を推測しない。** 再実行する。

## 対象範囲（意図的にやらないこと）

- **Claude Code のログのみ**。Codex（`~/.codex/`）は見ない。
- **`agent-*.jsonl` は集計外**。日報の主語は人間の作業で、サブエージェント内部の
  ツール実行まで数えると実態から乖離する。
- **週次・月次・長期トレンドは扱わない**。ログ保持は実測で約 1 ヶ月しかなく、
  90 日レンジの集計は「入力が沈黙したまま、それらしい出力が出る」形で劣化する。
  必要になったら、生ログではなく蓄積済みの `~/.claude/nippo/*.md` を入力にすること。
- **`~/.claude/history.jsonl` は見ない**。あれはプロンプトのみで行動が無く、
  `prompt-pattern-scan` が別目的で使う入力。

プロジェクトは cwd を git のトップレベルに畳んで数えている。**git worktree は別プロジェクト
として並ぶ**（`<repo>` と `<repo>-wt-pr1234` のように別々の行になる）。同じリポジトリの
作業だと分かる場合は、日報側で 1 つの見出しにまとめてよい。
